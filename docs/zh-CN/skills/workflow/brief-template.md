# 简报模板（七段，缺一段不派）

## 1. 目标
改完后哪里变简单、哪条行为变对。

## 2. 先核现状
下面的文件:行、函数名、行为先对照当前主线核；不一致就停下交回，不按过时的简报硬改。

## 3. 已查明的事实
`文件:行` + 一句结论，注明读自哪个提交。没实测的标"推出来的"。

## 4. 文件范围
- 可改：……
- 并行在改、不许碰：……（哪个包）
- 依赖与合入顺序：……

## 5. 不做什么
邻近但不属于本包的事。

## 6. 规矩（原样贴）
修根因不打补丁；不写防御性代码；一件事一个入口；简报外改动单列。改了归属或接口，归属记录的改动（large：`<docs_root>/ownership-map.md`；其余：系统页的 `## 怎么用`）写进交回，不改共享文档；自己文件里的注释和文档在同一提交里改。在自己的 worktree 里干，只 add 自己的文件（不用 `commit -a`），只本地提交，不 push。被提交检查拦下：改掉，或加一条带理由的 `allow` 并在交回里说明。
测试：只给"从代码难推对、又容易回退"的边界行为写；读代码就能确认的，在交回里写"读代码确认：文件:行"。一个测试只查一件事；不断言耗时；只跑改到的测试，不跑全套（全套在这批合并后跑一次）。
最后一次提交前，用 `nomess.py lessons add "<标题>" -s "<何时>" -b "<内容>" -k "<别名>" --unverified`（从仓库外学到的再加 `--external "<出处>"`） 把代码和 git 看不出来的事记下来，这样它就进了这次提交。

## 7. 交回清单
三项：提交；验证结果（check 结果一行；新增的测试和各自覆盖的验收项；读代码确认的项，写文件:行）；偏离方案的地方（前提不成立、看到了什么；简报外改动；没有写"无"）。查到的东西改变了决策时才加一行 `查过：<链接>`。

验收条件：
- 测试：……（变成测试用例的边界行为）
- 读代码确认：……（执行者在交回里给文件:行）

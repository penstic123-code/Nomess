# 审查清单

审查只看 `review-input` 的输出和设计片段。脚本已经报过的不用手工复查；必审部分里每个新的 `allow` 都要看：理由是不是真的，能不能改代码来解决。逐条过：

1. bug：边界、错误处理、并发、数据丢失。
2. 过度设计：只有一个实现的抽象；没人调用的选项、开关；"以防万一"的检查和回落路径；为几行加的依赖；能用标准库却自己写；重造仓库里已有的工具；测试太多、同一行为测两遍、测实现细节。
3. 补丁：钳制、特判、开关盖住症状，根因没动。
4. 重复与散落：同一件事两个入口；近乎重复该合并的代码；一个函数干几件不相干的事（按职责拆，不按行数）。
5. 耦合：直接读写别的模块的内部数据或私有函数；为了一个调用方把两个模块绑在一起；依赖方向和 `arch.layers` 相反。给出文件:行；修法是改走对方的公开入口。
6. 越界：改了范围外的文件；读写了别的系统拥有的数据却没改它的归属记录。
7. 误删：信任边界校验、防丢数据的错误处理、安全被删了。

每条必须给文件:行和具体例子，重读该行确认后再报。修法给最小的，优先删，不加层。带 `shortcut:` 注释且写明上限的算有意决定，不报。能机械判断的另列为"建议做成 check 规则"。

出处：分级与"具体例子 + 重读确认"借鉴自 ponytail 的 /ponytail-review（MIT）。
